What glide does

glide is inspired by Screen Studio on macOS. It records what you pick, then renders a finished video where your window sits on your wallpaper like a product demo.

  • Window or whole screenPick what to record in your desktop's own picker, or click the window on X11.
  • On your wallpaperCentered on your current wallpaper, a gradient or any image, with rounded corners and a soft shadow.
  • Camera that follows youOptional zoom that moves toward where you work and eases out as you move on.
  • Ripples on clicksA soft ring marks every click and touchpad tap, when you turn it on.
  • 4K, rendered on the GPUComposited in a GPU shader and encoded with hardware H.264 where available.
  • Screenshots tooOne frame, framed the same way, saved as a 4K PNG.

Install

The install script downloads the latest release for your machine, verifies its checksum, installs glide to ~/.local/bin and adds glide to your application menu.

$ curl -fsSL https://raw.githubusercontent.com/zNi0q/glide/master/install.sh | sh

Release builds exist for x86_64 and aarch64 and need glibc 2.39 or newer: Ubuntu 24.04, Debian 13, Fedora 40, Arch and newer.

Requirements

  • A Wayland or X11 session. On X11, a compositing window manager is needed for the glass toolbar.
  • ffmpeg and ffprobe, plus a GPU with Vulkan or OpenGL ES drivers.
  • On Wayland: PipeWire and xdg-desktop-portal with your desktop's backend (see Desktop support).

Install by hand

Download glide-<version>-<arch>-linux.tar.gz and its .sha256 from the latest release, then:

$ sha256sum -c glide-*-linux.tar.gz.sha256
$ tar -xzf glide-*-linux.tar.gz
$ install -Dm755 glide-*-linux/glide ~/.local/bin/glide

Build from source

Needs Rust 1.95 or newer, clang and the PipeWire development headers.

# Arch Linux
$ sudo pacman -S --needed rustup clang pipewire ffmpeg vulkan-icd-loader
# Debian or Ubuntu
$ sudo apt install clang libpipewire-0.3-dev libxkbcommon-dev ffmpeg libvulkan1
$ git clone https://github.com/zNi0q/glide && cd glide
$ cargo build --release

Quick start

  1. Run glide ui, or open glide from your application menu.
  2. Choose Window or Screen, and optionally a zoom level and click ripples under Effects.
  3. Press Record and pick what to record. On Wayland your desktop shows its picker; on X11, click the window (Esc cancels).
  4. Press ■ in the recording pill to stop. glide renders the 4K video and offers Open and Show in folder.

Prefer the terminal? Record with glide record myvideo, stop with Ctrl+C, then glide render myvideo -o myvideo.mp4.

The toolbar

glide ui shows a floating glass toolbar near the bottom of the screen. Drag it anywhere by its glass. Around it, clicks go straight through to your windows.

ControlWhat it does
Window / ScreenWhat the next recording or screenshot captures.
EffectsCursor-following zoom (Off, 1.5×, 1.8×, 2.5×) and the Show clicks toggle.
BackgroundYour wallpaper, a gradient, or any image you choose.
ScreenshotCaptures one polished 4K PNG.
RecordStarts recording. The toolbar becomes a small pill with a timer and ■ Stop.
✕ or EscCloses the toolbar.
The stop pill never appears in screen recordings

While recording the whole screen, the pill is invisible. Move the pointer to where it sits (bottom center unless you moved it) and it fades in. glide cuts the video just before the pill appeared.

Keyboard shortcut

Bind a shortcut such as Super+Shift+R to the full path of glide ui:

  • KDE Plasma: System Settings → Keyboard → Shortcuts → Add New → Command or Script.
  • GNOME: Settings → Keyboard → View and Customize Shortcuts → Custom Shortcuts.
  • COSMIC: Settings → Keyboard → Keyboard Shortcuts → Custom Shortcuts.
  • Hyprland: bind = SUPER SHIFT, R, exec, glide ui
  • Sway: bindsym $mod+Shift+r exec glide ui

Zoom and clicks

Cursor-following zoom

Off by default. When on, glide plans the camera after recording with a second of look-ahead: it zooms into the area where your cursor is busy, follows it, and eases back out when the cursor roams widely or rests. Every move is smoothed with springs.

Click ripples

glide records every click and touchpad tap while recording, so you can decide at render time whether to show them. A ripple appears at the cursor, grows and fades in under half a second.

On Wayland, clicks need one-time setup

Wayland does not let apps see clicks in other windows, so glide reads the mouse device directly. Add your user to the input group, then log out and back in. Members of input can also read keyboard input; glide only opens mouse and touchpad devices. X11 needs no setup.

$ sudo usermod -aG input $USER

Screenshots

Screenshots get the same treatment as videos: the window centered on your wallpaper with rounded corners, saved as a 3840×2160 PNG without the cursor. Press Screenshot in the toolbar, or:

$ glide screenshot -o shot.png
$ glide screenshot -o shot.png --screen

Output files

WhatWhere
Videos from the toolbar~/Videos/glide/ (your XDG videos directory)
Screenshots from the toolbar~/Pictures/glide/ (your XDG pictures directory)
Raw recordings~/.cache/glide/<date>/, kept so you can render again

A raw recording directory holds:

  • screen.mkv: the window, losslessly encoded at 60 fps without the cursor.
  • cursor.txt: one line per frame, x y in window pixels, or - when the cursor is outside.
  • clicks.txt: the frame number of every click, when clicks could be read.

Finished videos are 3840×2160 H.264 at 60 fps.

Updating

When a new version is released, the toolbar shows glide x.y.z is available with Update and Later. After updating, press Restart. From a terminal:

$ glide update

glide downloads the archive for your machine, verifies its checksum and replaces the installed binary.

How it works

Record Portal or X11 Composite→ Frames at 60 fps→ screen.mkv + cursor.txt + clicks.txt
Render ffmpeg decode→ GPU compute shader→ NV12→ VAAPI H.264→ 4K mp4
  • On Wayland the cursor is requested as metadata, so frames are recorded without it and its position is logged per frame. On X11, window contents come from the Composite extension.
  • The camera is planned offline with look-ahead and smoothed with critically damped springs.
  • A wgpu compute shader draws the wallpaper, rounded window, camera, ripples and cursor, and writes the hardware encoder's NV12 format directly.
  • Decoding, compositing and encoding run concurrently, so a 4K render runs at about real time on integrated graphics.

Troubleshooting

There are no click ripples in my video

Turn on Show clicks under Effects, or pass --clicks. On Wayland your user must be in the input group (see Zoom and clicks); the Effects menu says needs input access until it is.

The cursor is missing, or zoom does not follow it

Some portals cannot report the cursor separately. glide then records the cursor inside the video, which keeps it visible but means zoom cannot follow it.

"This desktop cannot share single windows"

Some portal backends only share whole screens. Choose Screen instead.

The release binary reports a GLIBC version error

Release builds need glibc 2.39 or newer. On older distributions, build from source.

The toolbar shows a black box on X11

The glass toolbar needs a compositing window manager for transparency. Enable your desktop's compositor, or use a desktop that has one.

Where did my recording go?

Videos go to ~/Videos/glide/, screenshots to ~/Pictures/glide/ and raw recordings to ~/.cache/glide/.

Development

$ cargo fmt
$ cargo clippy --all-targets -- -D warnings
$ cargo test
$ cargo test --release -- --include-ignored

The last command also runs the tests that need a GPU, ffmpeg, the portal or an X server.

Releasing

Every push to master is built and tested on GitHub Actions. To release, raise version in Cargo.toml, run cargo build so Cargo.lock follows, then commit and push. The workflow tags the version, builds x86_64 and aarch64 archives and publishes them, and installed copies offer the update.
